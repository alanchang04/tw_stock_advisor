## 0. 核心觀念：汙染不是資料的屬性

最常見的誤解是把資料分成「乾淨的」與「髒的」。**不是這樣。**

> **汙染是「你的決策」與「那份資料」之間的關係。**

同一份 2015~2026 資料，對 A 策略是髒的、對 B 策略可能是乾淨的——差別在於
**A 的假說是看著它長出來的，B 的不是**。

每一個你看著資料做的決定，都會消耗那份資料的證據力：

- 選哪一個因子
- 選哪一個窗長／門檻／持有期
- 決定什麼時候停止嘗試
- 決定「這次結果不算，因為我發現有 bug」

所以正確的問題不是「這份資料乾淨嗎」，而是
**「我看著它做過幾個決定，有沒有記下來」**。

### 0.1 真正致命的不是被看過，是不知道被看過幾次

| 情況 | 可否校正 | 為什麼 |
|---|---|---|
| 試了 4 個候選、有記錄 | ✅ | n_trials = 4，deflated Sharpe 直接處理 |
| 試了「很多次」、沒記錄 | ❌ | 不知道要打幾折，估計值永遠無法還原 |

本專案現行波段策略的問題**不在於它汙染**，而在於
`research/EXPERIMENTS.md` 記到 **≳126 次**累計試驗，且那還是保守下界。
n_trials 未知，Sharpe 就無法 deflate。

**推論**：與其追求「完全不碰資料」，不如**誠實記錄每一次碰觸**。
前者做不到，後者做得到。

## 1. 八個步驟

前一步沒過不得進下一步。**在早期步驟放棄是便宜的，在後期放棄是昂貴的。**

### 步驟 1：機制假說（無機制即停）

必須先回答，且**不准看任何資料**：

> **誰在虧錢？他為什麼非虧不可？**

好的答案長這樣（REV-1 §1.2）：融資追繳、處置導致的信用交易限制、基金贖回
——這些賣方不是看壞基本面，是**規則或槓桿逼他賣**，承接方賺的是流動性溢酬。
有明確因果方向。

不合格的答案：「這個指標在圖上看起來很準」「回測跑出來很好看」。
技術指標是**價格的描述**，不是價格的成因；描述不能當機制。

**否決權**：答不出來就停，不要進回測。

### 步驟 2：資料盤點＋獨立樣本數實測（仍不看任何報酬）

只用「不含報酬」的資訊回答三題：

1. **有沒有一段未被本假說的形成過程看過的期間？**
2. **那段期間有幾個「獨立事件」？**（不是幾筆交易，見 §2.2）
3. **辨識訊號所需的資料，在那段期間存在嗎？**

第 3 題最容易漏、也最致命。REV-1B 就死在這裡：它需要融資餘額，
但那要 2016-07 才有，holdout 期間 0 筆，**怎麼補都補不出來**。

**否決權**：獨立事件數不足或識別資料不存在，就不可能有統計結論。

### 步驟 3：可行性判定

四選一，必須明白寫下選了哪一條與理由：

| 選項 | 適用 |
|---|---|
| 補資料 | 官方來源存在且可重現（例：TWSE 處置歷史 604 筆） |
| 改事件定義 | 換一個有資料支撐的事件，但機制必須仍成立 |
| 只做 forward | backward 樣本不足，接受較慢的證據累積 |
| 放棄 | 前三者都不可行 |

**不可接受的第五條：放寬驗收門檻。** 那是在看過困難之後降低標準，
屬事後合理化。REV-1 §4 選修法 1 而非另外兩條，正是這個理由。

### 步驟 4：事前登記後凍結

把下列全部寫死並記錄 hash：

- universe 定義與每一個門檻值
- 訊號定義（精確到位移用交易日還是日曆日）
- 進場、出場、sizing、成本假設
- 驗收門檻
- **本輪變體總數**（見 §2.1）

登記進 `research/EXPERIMENTS.md`——**跑之前就登記**，不是跑完才補。

**這一步才是讓後面的測試有意義的東西。** 沒有事前登記，
後面的 holdout 只是另一次探索。

### 步驟 5：F0 實作正確性（不看績效）

驗證實作真的照規格做，全部與報酬無關：

- 無 look-ahead：竄改決策日之後的資料，訊號必須逐位元不變
- 無倖存者偏誤：PIT universe，下市後不得 forward-fill
- 單位正確：股 vs 張、成交金額 vs 成交量
- 時間對齊：月末取實際交易日、位移以交易日計
- 不可成交狀態：停牌、漲跌停鎖死、處置、變更交易
- 相同輸入兩次結果完全一致

**F0 未全通過不得進入步驟 6。**

### 步驟 6：開封 holdout ——一次

- 只跑一次，結果不論好壞立刻寫入登記簿
- **這是否證測試，不是背書**（見 §3.3）
- 不得因為結果不好就換個名字重測同一個想法

### 步驟 7：累計試驗次數並套用 deflated Sharpe

n_trials 只增不減，跨策略累加，永遠不歸零。

### 步驟 8：forward paper trading

**唯一的正面證據來源。** 它同時免除制度外推問題——
forward 期間用的就是現行漲跌幅、現行撮合方式、現行產業結構。

## 2. 三個最容易算錯的東西

### 2.1 什麼算「一次試驗」

**探索也是試驗。** 這是本專案付出最大代價的一課。

看 IC 表挑因子、比較四個窗長挑最好的、掃描門檻找轉折點
——這些在當下感覺像「研究」，但它們**每一次都在消耗資料的證據力**，
效果與跑一次回測相同。

| 動作 | 算幾次試驗 |
|---|---|
| 比較 4 個形成窗、選最好的 | **4** |
| 掃描 6 個停損檔位 | **6** |
| 出場消融一次拔 12 條規則 | **12** |
| 「先看看 IC 長怎樣」 | **看了幾個因子就是幾次** |
| 發現 bug 後重跑 | 0（修正不算新變體，但差異必須記錄） |

### 2.2 樣本單位是「獨立情境」不是「交易」

一次市場性急殺同時觸發 20 檔進場，那**不是 20 個獨立樣本**，
橫斷面相關性接近 1。

- 情境定義：事件日相距 N 個交易日以內者歸為同一情境（本專案 N=10）
- 必報獨立情境數
- **獨立情境數 < 30 不得宣稱任何統計顯著性**，只能報告為觀察
- 標準誤採情境層級 cluster，不得用交易筆數算 t 值

實例：REV-1A 有 144 個股票－事件，但只構成 35 個獨立情境
——直接用 144 算 t 值會把有效樣本數誇大約 4 倍。

### 2.3 制度差異

跨年代測試必須逐項揭露制度差異。台股已知的：

| 項目 | 變更 |
|---|---|
| 漲跌幅限制 | ±7% → ±10%（2015-06-01） |
| 撮合方式 | 集合競價 → 逐筆交易（2020-03） |
| 現股當沖 | 逐步開放 |
| 盤中零股 | 2020-10 起 |

**慢策略（月頻換股、持有數月）受微結構變化影響小；
短線／日內策略受影響大。** 評估時要說明本策略屬哪一類。

## 3. 資料該怎麼分配

### 3.1 決策樹

```
這個假說是怎麼來的？
├─ 從回測／IC 表／參數掃描挖出來的
│   └─ 那段資料對本策略已污染 → 必須用「它沒看過的期間」驗收
└─ 從機制推導或外部觀察來的
    └─ 全部歷史資料都可用 → 但仍須事前登記後才准跑
```

**這直接回答「為什麼不能用最近幾年的資料」：**
可以，前提是**那套策略的假說不是從最近幾年的資料裡挖出來的**。

### 3.2 本專案現況

| 策略 | 假說來源 | 已污染期間 | 可用驗收期間 |
|---|---|---|---|
| 現行波段 | 反覆調參，n_trials ≳126 | 2015~2026 | 無（證據力已用盡） |
| MOM-1 | 2026-08-11 的 IC 表擇一（4 選 1） | 2015~2026 | 2008~2014、forward |
| REV-1 | 2026-07-19 P1 因子研究發現 rs20 負 ICIR | 2015~2026 | 2008~2014、forward |
| **下一套** | **尚未開始 → 可以完全乾淨** | **無** | **全部** |

### 3.3 holdout 結論的效力是不對稱的

| 結果 | 可以宣稱 | 不可以宣稱 |
|---|---|---|
| 未通過 | 已被否證，正式否決 | — |
| 通過 | 「在該期間的市場制度下沒有被否證」 | ❌「有效」❌「可部署」 |

通過 holdout 的實際價值是**省下 12 個月的 forward paper**，不是正面證據。

## 5. 常見失敗模式（皆為本專案實例）

| 模式 | 實例 | 代價 |
|---|---|---|
| 先寫規格、後盤點資料 | REV-1 v1.0 帶著一個不可能通過的門檻 | 規格重寫 |
| 探索不計入試驗次數 | MOM-1 的形成窗是 4 選 1，當時未登記 | 汙染 2015~2026 |
| 把描述當機制 | 技術指標「看起來很準」 | 無法區分 edge 與雜訊 |
| 用交易筆數算顯著性 | 見 §2.2 | 有效樣本誇大數倍 |
| 缺資料補 0 | 早期不揭露的欄位補 False | 把「不知道」說成「沒有」 |
| 門檻法取代精確規則 | `change_pct >= 6.9%` 判漲停 | 漏掉 54% 的真實漲停日 |
| 結果不好就改門檻 | —（本專案以修法 1 避開） | 事前登記保護失效 |

## 6. 判決規則

- 結論欄只能填 **採用 / 否決 / 待驗**，不准填模稜兩可的形容詞
- 失敗的策略**正式否決並寫入登記簿**，不得原地微調搶救
- 下一步只能是換一類機制，不是換一組參數
- 否決的紀錄要留得比採用的更完整——避免日後有人重做一次
